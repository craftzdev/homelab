# ADR-0008: バックアップを 3 階層（etcd / Velero / PBS）で構成する

- **状態**: 承認済み
- **日付**: 2026-08-30

## 背景

脅威 T10（可用性の喪失・ランサムウェア）への対処として、
「どこまで壊れたら、何を使って、どこまで戻せるか」を明確にする必要がある。

Ceph は replica 3 で冗長化されているが、**冗長化はバックアップではない**。
誤って `kubectl delete pvc` した場合も、Ceph が論理的に壊れた場合も、
レプリカは 3 つ全てが同じように失われる。

## 障害シナリオと必要な復旧手段

| # | シナリオ | Ceph replica で救えるか | 必要な手段 |
| --- | --- | --- | --- |
| S1 | OSD が 1 本故障 | ✅ 救える | — |
| S2 | Kubernetes リソースを誤削除（Deployment 等） | ✗ | Git（宣言が残っている） |
| S3 | PVC を誤削除 | ✗ | **Velero / snapshot** |
| S4 | etcd の破損・クラスタ全損 | ✗ | **etcd スナップショット** |
| S5 | Ceph クラスタの論理破損 | ✗ | **クラスタ外へのバックアップ** |
| S6 | ランサムウェアによる暗号化 | ✗ | **オフライン/別筐体のバックアップ** |
| S7 | 物理的な災害（火災・盗難） | ✗ | オフサイト（本 ADR ではスコープ外） |

## 決定

**3 階層のバックアップを構成する。**

### 階層 1: etcd スナップショット（→ S4）

Kubernetes クラスタの状態そのもの。Talos が API 経由でスナップショットを取得できる。

```bash
talosctl -n 172.16.40.11 etcd snapshot ./etcd-$(date +%F).snapshot
```

- 保存先: 運用端末 + PBS（VM バックアップに含まれる）
- 頻度: 日次（CronJob 化、または運用端末の cron）
- 復旧: `talosctl bootstrap --recover-from=` で復元

> **注**: GitOps を徹底していれば、クラスタは Git から再構築できる。
> ただし etcd スナップショットがあれば復旧が圧倒的に速い。

### 階層 2: Velero（→ S3, S5）

namespace 単位でのアプリケーション + PVC のバックアップ。
ceph-csi の VolumeSnapshot と連携し、CSI スナップショットを取得する。

- 保存先: **クラスタ外のオブジェクトストレージ**
  - 初期: クラスタ内 MinIO（S5 には無力。あくまで S3 対策）
  - **推奨**: 外部 S3 互換（Cloudflare R2 等）または PBS 上の MinIO
- 頻度: 日次（重要 namespace）
- 保持: 30 日

> ⚠️ **重要な注意**: Velero のバックアップ先をクラスタ内 MinIO にした場合、
> その MinIO 自体が Ceph 上にある。**Ceph が壊れればバックアップも消える**。
> 旧リポジトリの構成（`minio-for-velero`）はこの問題を抱えていた。
> 本構成では**バックアップ先を外部に置くことを既定とする**。

### 階層 3: Proxmox Backup Server（→ S5, S6）

VM 丸ごとのイメージバックアップ。PBS は 172.16.10.51 で稼働中。

- 対象: Kubernetes ノード VM 6 台
- 頻度: 週次（Talos はステートレスに近いため日次は不要）
- 保持: 4 世代
- **PBS は Ceph とは別の物理筐体にある**ため、S5/S6 に対して有効

### snapscheduler（補助）

Ceph 内で定期的に VolumeSnapshot を取る。
**S3（誤削除）からの高速復旧専用**であり、S5/S6 には無力。
「バックアップではなく、Undo ボタン」と位置づける。

## 復旧目標

| 指標 | 目標 | 根拠 |
| --- | --- | --- |
| RPO（目標復旧時点） | 24 時間 | 日次バックアップ。ホームラボとして妥当 |
| RTO（目標復旧時間） | 4 時間 | IaC により再構築が自動化されているため |

## 検証

**バックアップは復元テストをして初めてバックアップである。**

四半期に 1 度、以下を実施する。

1. Velero で 1 つの namespace を別名で restore し、Pod が起動することを確認
2. etcd スナップショットからの復旧手順を書面で確認（実機テストは年 1 回）
3. PBS から VM を 1 台テストリストアする

結果は `docs/50-operations.md` の運用記録に追記する。

## トレードオフ

- ❌ 3 階層は運用負荷が高い
  → Velero と PBS はスケジュール実行で自動化し、人手は検証のみに使う
- ❌ 外部 S3 にはコストがかかる
  → Cloudflare R2 は egress 無料。ホームラボの規模なら月額数百円以内
